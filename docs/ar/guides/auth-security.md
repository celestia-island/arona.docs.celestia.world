# المصادقة والأمان

تُصادق Arona المتصلين عبر مسارين: **رموز جلسات JWT** للعملاء التفاعليين
(واجهة المحادثة + الإدارة، استدعاءات RPC) و**مفاتيح API** (`arona-…`)
لحركة المرور البرمجية المتوافقة مع OpenAI. يحرس token إداري منفصل الأسطح
الإدارية. توثّق هذه الصفحة الآليات ونموذج الأمان والبقايا المعروفة
منخفضة الخطورة من تدقيق أمني.

## جلسات JWT

تستخدم الجلسات أزواج رموز وصول/تحديث JWT تصدرها مدير رموز
`kirino_session`:

- **TTL لaccess token: 900 ثانية (15 دقيقة).**
- **TTL لrefresh token: 604,800 ثانية (7 أيام).**

تُصادق رموز الوصول مستوى JSON-RPC (`/api/rpc`) و`GET /v1/models`؛ يُربط
المكوّن الجانبي SSE (`/api/rpc/events`) بمعرّف الجلسة، وهي قدرة تُسكّ أثناء
استدعاءات RPC المُصادَق عليها وليست بيانات اعتماد bearer. تتطلب نقاط نهاية
`/v1/chat/completions` و`/v1/embeddings` و`/v1/video/*` **مفتاح API** (لا
يُقبل JWT هناك). رموز الوصول قصيرة العمر حتى لا يُستخدم token مسروق إلا
لفترة وجيزة. تُستبدل رموز التحديث بأزواج جديدة عبر `auth.refresh`.

يستخدم التحديث **تدوير عائلة tokens (token-family rotation)**: استهلاك refresh token يُبطله ويُصدر واحدًا جديدًا، وإعادة استخدام refresh token مستهلك تُلغي
العائلة كلها — يجيب `auth.refresh` بـ`AUTH_ERROR` مع الرسالة
`Refresh token reused` (الخطأ الكامن هو `TokenReused`، «أعيد استخدام refresh token — أُلغيت عائلة tokens»)، ويجب أن يسجّل الحساب الدخول مجددًا.
إلغاء العائلة **في الذاكرة** (مجموعة `revoked_families`): إعادة تشغيل
الخادم تمسحها، لذا تكون الحماية بأفضل جهد عبر عمليات إعادة التشغيل (حالة
جلسة المستخدم لا تنجو من إعادة التشغيل).

يأتي سر التوقيع من متغير البيئة `JWT_SECRET`. خارج `MOCK_MODE=1` **يرفض
الخادم الإقلاع** إذا كان `JWT_SECRET` غير مضبوط أو ما زال يساوي سر التطوير
المدمج، فلا يمكن لمثيل إنتاج أن يخدم عن غير قصد رموزًا موقَّعة بثابت عام.
استخدم سرًا قويًا عشوائيًا ولا تُودِعه في git أبدًا.

## مفاتيح API

مفاتيح API هي بيانات الاعتماد الآلية للسطح المتوافق مع OpenAI:

- **الصيغة:** `arona-{uuid}`.
- **التخزين:** لا يُخزَّن في جدول `api_keys` إلا **هاش SHA-256** للمفتاح —
  يُعاد النص الصريح مرة واحدة فقط، في استجابة `keys.create`، ولا يمكن
  استرجاعه لاحقًا أبدًا.
- **بادئة المفتاح:** تُخزَّن الأحرف الثمانية الأولى (`key_prefix`) بنص
  واضح للعرض وإسناد الاستخدام؛ تعرض الواجهة شكلًا مقنّعًا مثل
  `arona-XXXX…abcd`.
- **الإبطال:** بحث المفتاح يضم `api_keys.is_active = TRUE`، لذا يتوقف
  المفتاح المُبطَل عن التحقق فورًا — لا يوجد TTL لذاكرة مؤقتة تنتظر
  انقضاءه.

## المستويات الإدارية

هناك ثلاث بوابات إدارية متميزة، ولكل منها بيانات اعتماد خاصة بها:

1. **مسارات `/api/admin/*`** — إدارة الـ backends والـ aliases
   (`POST/GET/DELETE /api/admin/backends`،
   `POST/GET/DELETE /api/admin/aliases`) تتطلب ترويسة
   `Authorization: Bearer ARONA_ADMIN_TOKEN`. عندما لا يكون
   `ARONA_ADMIN_TOKEN` مضبوطًا، يفشل `check_admin` دائمًا ويعيد كل مسار
   إداري **401 "Admin access required"** — يُعطَّل سطح الإدارة بالكامل
   بدلًا من فتحه.

2. **طرق RPC `agents.*` و`engine.invoke`** — تتطلب مجموعة الـ agent
   ومستوى التحكم في المحرك JWT يكون فيه للحساب `users.is_admin = true`.
   يُرفض المستخدم غير المشرف المُصادَق عليه بالكود المعرَّف في التنفيذ
   **-32007 (`ADMIN_REQUIRED`)** مع تلميح خاص بالطريقة (مثل
   `agents.deploy starts model deployments on GPU nodes`)؛ المتصل **غير
   المُصادَق عليه** يحصل على **-32005 (`AUTH_ERROR`)** القياسي حتى لا
   يكشف الخادم أن الطريقة مميزة أصلًا.

3. **طريقتا RPC `billing.plan.set` و`billing.video.pricing.set`** —
   تتطلب تحويرات الفوترة نفس `ARONA_ADMIN_TOKEN` من نوع Bearer كمسارات
   HTTP الإدارية؛ وبدونه تعيد `AUTH_ERROR` "Admin access required".

**أول مستخدم مسجَّل يصبح المشرف** (`users.is_admin = true`). كل تسجيل
لاحق يكون مستخدمًا عاديًا، والتسجيل مفتوح فقط بينما يكون
`ARONA_REGISTRATION_OPEN` مضبوطًا على قيمة صادقة.

## سياسة كلمات المرور

يجب أن تستوفي كلمات المرور **كلتا** القاعدتين (تُنفَّذان عند التسجيل وفي أي
مسار لتغيير كلمة المرور):

- 8 أحرف **على الأقل**، و
- 3 من فئات الأحرف الأربع **على الأقل**: أحرف كبيرة، صغيرة، رقمية، خاصة.

## تحديد المعدل

يعمل تحديد المعدل على مسارين مستقلين؛ أيُّهما يمكن أن يرفض طلبًا
بـ**429**:

### 1. نافذة منزلقة في الذاكرة (لكل هوية)

يمر كل طلب `/v1` مُصادَق عليه عبر محدّد نافذة منزلقة في الذاكرة مفاتيحه
هوية المتصل:

- **استدعاءات مفتاح API** مفاتيحها **هاش SHA-256** للمفتاح؛
- **استدعاءات JWT** مفاتيحها `u:<email>` — تدور JWTs كل 15 دقيقة، لذا فإن
  جعل النافذة بمثيل الـ token نفسه سيعيد ضبطها بصمت عند كل تحديث.

الميزانية الافتراضية **60 طلبًا في الدقيقة**، قابلة للتجاوز بـ
`ARONA_API_RATE_LIMIT_RPM` (اضبطها أعلى لخطوط أنابيب الـ agent التي تُطلق
العديد من استدعاءات LLM المتوازية). ضبطها على **0 يحجب كل طلب**.

### 2. حد معدل الطبقة (لكل مفتاح، من قاعدة البيانات)

تحمل طبقات الفوترة `rate_limit_rpm` لكل مفتاح. يعدّ الفحص صفوف
`usage_records` لبادئة المفتاح في **الستين ثانية الماضية** (يُستمر
الاستخدام بعد كل استجابة، لذا تتأخر النافذة بطلب واحد قيد الطيران على
الأكثر؛ فشل قاعدة البيانات يُعامَل بفتح (fail open)). **الطبقة المجانية
المبدئية هي 10 RPM**؛ طبقات pro/enterprise ترفع السقف. يشارك إنفاذ الحصة
الشهرية نفس مسار الرفض.

### تحديد معدل تسجيل الدخول

يُخنق تخمين بيانات الاعتماد عند نقطة تسجيل الدخول: **5 محاولات فاشلة لكل
نافذة 5 دقائق لكل بريد إلكتروني** و**20 لكل نافذة 5 دقائق لكل IP**، تلي
كلًا منها إقفال لمدة 15 دقيقة.

### `Retry-After`

تحمل كل استجابة 429 ترويسة `Retry-After` حتى يتراجع العملاء المتوافقون
مع OpenAI بدلًا من قصف نقطة النهاية: رفض الحصص يضبطها على **ثوانٍ حتى
نهاية الشهر**؛ رفض تحديد المعدل يضبطها على **60**. انظر [الفوترة
والاستخدام](billing-usage.md) لنموذج الحصص.

## ملاحظات نموذج الأمان

- **CORS يسمح بأي أصل** (`allow_origin(Any)`) — Arona backend تستهلكها
  عملاء أوليون وثالثيون كثيرون؛ إذا كان نشرك يجب أن يقيد الأصول، ضَع
  أمامه وكيلًا عكسيًا يفرض CORS.
- **أجسام الطلبات محدودة بـ 1 MB** (`RequestBodyLimitLayer`)، ما يحدّ من
  استخدام الذاكرة على الـ gateway.
- **لا ينهي الـ gateway أي TLS** — يستمع على HTTP عادي. ضعه خلف وكيل
  عكسي (انظر [النشر](deployment.md)) ينهي HTTPS.
- **الأسرار تأتي من البيئة فقط**: يُقرآن `ARONA_ADMIN_TOKEN` و`JWT_SECRET`
  من متغيرات البيئة، ويجب أن يكونا قيمتين عشوائيتين قويتين لا تُودعان في
  المستودع أبدًا.
- عنوان الربط الافتراضي للخادم هو `0.0.0.0`؛ قيّد التعريض في طبقة
  الشبكة.

## بقايا معروفة منخفضة الخطورة (من التدقيق)

ما يلي موثّق كما هو؛ مقصود أو مقبول حاليًا، لكن جدير بالمعرفة عندما تعرّض
مثيلًا خارج شبكة موثوقة:

- **`providers.list` عامة**، بينما تتطلب `providers.add` / `providers.update`
  / `providers.remove` / `providers.test` JWT. يكشف مسار القراءة العام
  كتالوج الـ providers لكن لا شيء سريًا.
- **`/ws/agent` مستوى تحكم غير مُصادَق عليه**: تتصل وكلاء GPU دون أي بيانات
  اعتماد ويسجّلون أنفسهم (أطر `register` / `heartbeat` / command-result).
  أي شخص يستطيع الوصول إلى منفذ WebSocket يستطيع تسجيل وكيل مزيف. انظر
  [مجموعة الـ Agent](agent-cluster.md) للمفاضلات التشغيلية.
- **`memory.delete` يقتصر على JWT دون فحص ملكية**: يمكن لأي مستخدم مُصادَق
  عليه حذف عقدة ذاكرة عبر `node_id`. حذف الذاكرة يتطلب تسجيل الدخول، لكن
  لا يتطلب امتلاك العقدة.
